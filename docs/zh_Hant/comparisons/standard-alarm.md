# BarcodeWake 與標準鬧鐘的比較

BarcodeWake 為預設鬧鐘新增一項可驗證的關閉任務，而標準鬧鐘通常只需一個附近的控制即可停止。這額外的障礙可以中斷自動貪睡，但同時也帶來了設定、硬體和無障礙方面的考量。

## 實務上的差異在於關閉方式

傳統手機或床頭鬧鐘設定快速、靜音也快速。當聲音本身已足夠時，這種簡單性是合適的。但對於那些關閉鬧鐘卻沒有形成清晰記憶的人來說，這就成為了弱點。

BarcodeWake 將決策轉變為一項任務。放置在離床較遠處的條碼需要伸手並掃描物品。數學或打字需要專注。搖晃或走路需要移動。電流來源還可以結合任務或從中選擇一個。這些方法都不會測量使用者是否在生物學上已清醒；它們只驗證是否完成了定義的互動。

| 考量事項 | BarcodeWake | 標準鬧鐘 |
|---|---|---|
| 關閉方式 | 掃描、認知任務或移動 | 通常一個按鈕或手勢 |
| 設定 effort | 任務、權限和測試 | 時間、天數和聲音 |
| 硬體相依性 | 部分任務需要相機或感測器 | 喇叭或震動 |
| 自動貪睡抗拒力 | 可能需要距離或 effort | 通常有限 |
| 無障礙存取 | 必須仔細選擇任務 | 較簡單的互動 |
| 可靠性邊界 | 作業系統和供應商控制 | 裝置電源和鬧鐘實作 |

## 針對特定失敗模式選擇 BarcodeWake

當問題不是聽不到鬧鐘而是自動關閉鬧鐘時，這是更好的選擇。另一個房間中的穩定條碼創造了螢幕上謎題無法做到的情境轉換。認知任務可能適合旅行，因為無法使用永久的實體條碼。如果已安裝版本支援，隨機或連鎖任務可以減少習慣化。

使用[任務指南](../features/missions.md)將任務與環境匹配。當移動任務造成跌倒風險、打擾他人或與行動需求衝突時，應避免使用。導致停用應用程式的苛刻任務比可持續的適度任務更糟糕。

## 為高後果的早晨保留標準備用方案

基於任務的關閉方式不會移除手機層級的失敗模式。權限、電池優化、音量和供應商限制仍然重要。對於航班、醫療預約或其他高後果事件，請使用第二個獨立鬧鐘，直到設定在真實過夜條件下經過測試。

遵循[設定和測試程序](../guides/set-up-an-alarm.md)，然後保留[傳遞檢查清單](../help/alarm-delivery.md)。如果簡單的床頭鬧鐘已經可靠地運作，而且意外關閉不是問題，那麼 BarcodeWake 的額外障礙可能提供的幫助微乎其微。
