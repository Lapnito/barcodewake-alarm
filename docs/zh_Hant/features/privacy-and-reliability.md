# BarcodeWake 隱私和鬧鐘可靠性

BarcodeWake 將已記錄的鬧鐘配置和任務資料保存在設備上，無需應用程式帳戶。目前的程式碼路徑會對註冊的代碼值進行雜湊處理。可選的遙測功能描述為預設停用，而鬧鐘傳遞仍取決於系統權限和供應商控制。

## 本地資料無法移除系統依賴

本地儲存表示一般的鬧鐘設定不需要 BarcodeWake 雲端帳戶。鬧鐘記錄、歷史和偏好設定透過應用程式的本地資料層處理。註冊的條碼、QR 碼和 NFC 值在目前的儲存和匯入路徑中以 SHA-256 雜湊表示，這樣可以避免保留用於匹配的普通原始值。

雜湊與每個應用程式記錄的加密不同，本地儲存也不是備份。擁有解鎖設備存取權限的人仍可透過應用程式查看鬧鐘名稱、行程或歷史。遺失或重置的手機也可能遺失本地資料，除非使用者有進行匯出。請參閱[備份與分享](../guides/backup-and-sharing.md)以了解各格式及其不同用途。

隱私權政策指出可選的遙測功能預設為關閉，並描述了啟用時的匯總處理方式。因此，本文件不做出應用程式永遠無法透過網路通訊的更廣泛聲明。它陳述了更狹窄的已驗證事實：核心操作和資料是本地的，不需要產品帳戶，且在檢查的專案中未發現廣告 SDK 依賴。

## 可靠性是共同責任

BarcodeWake 可以排程和顯示鬧鐘，但作業系統決定背景工作何時可以執行以及允許哪些中斷。通知權限、精確鬧鐘存取、靜音或專注模式、電池優化、應用程式自動暫停和製造商的任務終止工具都可能有所影響。應用程式內的可靠性工具可以識別配置風險並引導使用者進行設定；但無法覆寫系統政策。

安裝後，請在螢幕鎖定且手機處於過夜使用的相同電源模式下進行測試。在系統更新、省電模式變更或應用程式重新安裝後重複該測試。保持設備充電、音量適當，並確選擇的任務在實體上可用。當測試失敗時，請遵循[鬧鐘傳遞疑難排解](../help/alarm-delivery.md)。

## 隱私和可靠性不承諾的事項

BarcodeWake 不是醫療裝置、緊急警報服務或睡眠階段追蹤器。沒有任何鬧鐘應用程式可以保證喚醒或補償設備不可用的情況。[事實與限制頁面](../facts.md)列出了這些界限，而[可用性](../availability.md)則將公開商店的證據與較新的來源功能分開。
