# BarcodeWake 与标准闹钟的比较

BarcodeWake 为预设闹钟添加了一个可验证的关闭任务，而标准闹钟通常只需附近的一个控件即可停止。这种额外的摩擦可以中断自动贪睡行为，但同时也带来了设置、硬件和可访问性方面的考量。

## 实际的区别在于关闭方式

传统的手机或床头闹钟配置简单，关闭也快捷。当声音本身就足够时，这种简单性是恰当的。但对于那些在关闭闹钟时没有形成清晰记忆的人来说，这就变成了一个弱点。

BarcodeWake 将决策转化为一个任务。放置在远离床头的条码需要伸手去扫描。数学或打字任务需要集中注意力。摇晃或步行任务需要身体移动。电流源模式也可以组合任务或从多个任务中选择一个。这些方法都不衡量用户是否在生理上清醒；它们只验证是否完成了定义的交互动作。

| 考量 | BarcodeWake | 标准闹钟 |
|---|---|---|
| 关闭方式 | 扫描、认知任务或移动 | 通常一个按钮或手势 |
| 设置难度 | 任务、权限和测试 | 时间、天数和声音 |
| 硬件依赖 | 某些任务需要摄像头或传感器 | 扬声器或振动 |
| 抵抗自动贪睡 | 可能需要距离或努力 | 通常有限 |
| 可访问性 | 必须谨慎选择任务 | 交互更简单 |
| 可靠性边界 | 操作系统和厂商控制 | 设备电量和闹钟实现 |

## 为特定的故障模式选择 BarcodeWake

当问题不是听不到闹钟而是自动关闭闹钟时，它更合适。另一个房间里的稳定条码创造了屏幕上的谜题无法实现的上下文转换。认知任务可能适合旅行，因为那时无法使用固定的物理条码。如果安装的版本支持的话，随机或链式任务可以减少习惯化。

使用[任务指南](../features/missions.md)将任务与环境相匹配。避免在会产生跌倒风险、打扰他人或与行动需求冲突的情况下使用移动任务。导致禁用应用的高难度任务比保持可持续性的适度任务更糟糕。

## 为高风险早晨保留标准备用方案

基于任务的关闭方式并不能消除手机层面的故障模式。权限、电池优化、音量和厂商限制仍然很重要。对于航班、医疗预约或其他高风险事件，请使用第二个独立闹钟，直到设置在真实的过夜条件下测试通过。

遵循[设置和测试步骤](../guides/set-up-an-alarm.md)，然后保留[送达清单](../help/alarm-delivery.md)。如果简单的床头闹钟已经可靠地工作，而且意外关闭不是问题，那么 BarcodeWake 额外的摩擦可能提供的益处微乎其微。
