# 安全备份和共享 BarcodeWake 闹钟

在保存或迁移自己的应用数据时使用 JSON 导出，在恢复时使用可打印的 PDF 备份条码，在只需要闹钟结构时使用设置二维码共享。共享时特意省略注册的密钥和历史记录。

## 选择适合任务的格式

当前源码提供不同的交换路径，因为备份和共享不是同一操作。JSON 备份用于结构化数据传输和恢复。PDF 备份将恢复材料转换为可打印的条码文档。设置二维码则特意更窄：它只能传递有限的闹钟配置，而不携带注册的条码值、NFC 标识符、PIN 或历史记录。

不要将设置二维码视为完整的设备备份。接收者必须自行注册其物理码并在本地审查权限。当前的设置共享也会限制其携带的闹钟数量，因此请验证导入结果，而不是假设所有日程都已移动。[产品事实](../facts.md) 记录了这些限制。

## 创建并保护个人备份

使用安装版本中提供的导出操作，根据恢复计划选择 JSON 或可打印备份，并将结果保存到您控制的位置。备份可能会显示闹钟名称、日程及其他配置，即使原始码值已被保护或省略。将其视为个人常规数据处理：避免公共链接、共享打印机和不可信的通讯渠道。

导出后，确认文件可以被找到，并且其时间戳与预期的备份相符。不要仅仅因为导出命令报告成功就删除原始应用数据。恢复测试是唯一可靠的检查，但应在安全设备上或制作副本后再进行，以免测试本身成为丢失事件。

## 共享设置而不共享密钥

仅为接收者应接收的闹钟生成设置二维码。接收者扫描二维码，查看导入的日程，并提供自己的码、NFC 标签或恢复详情。此设计防止共享配置在不知不觉中转移用于关闭他人闹钟的物理密钥。

导入后，每个人都应运行完整的[闹钟设置测试](set-up-an-alarm.md)。权限、传感器和操作系统限制不会在二维码中转移。如果导入的闹钟在锁定状态下未能出现，请参考[闹钟传递故障排除](../help/alarm-delivery.md)。

在本次审计期间，源码版本和商店版本存在差异，因此已安装的公开版本可能不会显示此处描述的所有交换选项。[可用性](../availability.md) 说明了如何解释仅在源码中提供的功能。
