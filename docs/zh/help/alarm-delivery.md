# 为什么 BarcodeWake 闹钟可能不响

已保存的闹钟仍可能被通知设置、精确闹钟访问权限、专注或静音模式、低音量、电池限制、应用暂停或厂商后台控制所阻挡。请将送达与任务扫描分开检查，然后进行锁屏测试。

## 首先将送达与取消分离

创建一个短期测试闹钟，设置一个简单的任务，并将应用留在后台。锁定屏幕。如果没有出现闹钟界面或声音，则问题在于送达；更改注册的条码无法解决。如果闹钟出现但任务无法完成，则送达正常，问题在于摄像头、传感器、代码匹配或任务配置。

确认闹钟已启用、预定日期正确且手机时区与计划时间匹配。检查媒体音量和闹钟音量，而不仅仅依赖侧边按钮状态。检查勿扰或专注规则、已连接的音频设备，以及创建闹钟后是否重启了手机。

## 检查操作系统权限

允许通知以及安装版本请求的任何精确闹钟或全屏闹钟访问权限。当设备厂商提供相关控制时，将 BarcodeWake 从激进的电池优化或自动休眠列表中移除。打开应用内可靠性诊断并遵循其识别的设备特定设置。[隐私和可靠性页面](../features/privacy-and-reliability.md)解释了为什么即使应用数据是本地存储的，这些系统依赖项仍然存在。

更改一个设置后，重复锁屏测试。一次更改多个控件会使原因更难识别。系统更新可能会重置或重新解释权限，因此在重大更新或应用重新安装后重新测试。

## 单独诊断任务完成情况

对于条码和二维码任务，请清洁摄像头镜头、改善照明并确认注册的对象未更改。授予摄像头权限。对于 NFC，请验证设备支持并将标签靠近正确的天线位置。摇晃和步数任务依赖于运动或步数传感器，当节能模式限制传感器送达时可能会有不同的表现。

如果任务配置为链的一部分，则每个必需的步骤都必须完成。查看[任务行为](../features/missions.md)，如有必要，使用[设置程序](../guides/set-up-an-alarm.md)创建新的测试。

## 了解手机何时是限制因素

BarcodeWake 无法覆盖已关机设备、电量耗尽的电池、损坏的音频硬件或每个制造商的任务杀手。它不是紧急通知服务。在高风险情况下保持另一种闹钟方法，并用设备型号、系统版本、应用版本和确切的测试条件报告可重现的故障。
