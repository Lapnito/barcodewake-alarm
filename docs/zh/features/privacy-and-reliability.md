# BarcodeWake 隐私与闹钟可靠性

BarcodeWake 将已记录的闹钟配置和任务数据保存在设备上，不需要应用账号。当前的代码路径会对已注册的码值进行哈希。可选的遥测功能被描述为默认关闭，而闹钟的发送仍依赖于系统权限和供应商控制。

## 本地数据不会消除系统依赖

本地存储意味着普通的闹钟设置不需要 BarcodeWake 云账户。闹钟记录、历史和偏好通过应用的本地数据层处理。已注册的条码、二维码和 NFC 值在当前的存储和导入路径中以 SHA-256 哈希表示，这避免了在匹配时保留原始值。

哈希并不等同于对每条应用记录进行加密，而本地存储也不是备份。拥有已解锁设备访问权限的人仍可能通过应用看到闹钟名称、日程安排或历史记录。丢失或重置手机也可能导致本地数据丢失，除非用户已经进行了导出。参见[备份与共享](../guides/backup-and-sharing.md)了解各种格式及其不同用途。

隐私政策指出可选遥测默认关闭，并描述了如果启用时的聚合处理方式。因此，本文档不会做出更广泛的声明——即该应用永远不会通过网络通信。它仅陈述经过验证的狭窄事实：核心操作和数据是本地的，不需要产品账号，并且在检查的项目中未发现广告 SDK 依赖。

## 可靠性是共同责任

BarcodeWake 可以安排并显示闹钟，但操作系统决定后台工作何时运行以及允许哪些中断。通知权限、精确闹钟访问、静音或专注模式、电池优化、自动应用挂起以及制造商的任务终止器都可能产生影响。应用内的可靠性工具可以识别配置风险并引导用户进入相应设置，但不能覆盖系统策略。

安装后，请在屏幕锁定且手机使用与夜间相同的电源模式下进行测试。在系统更新、节电模式更改或应用重新安装后重复该测试。保持设备充电、音量合适，并确保所选任务在物理上可用。当测试失败时，请按照[闹钟发送故障排除](../help/alarm-delivery.md)进行操作。

## 隐私和可靠性不承诺什么

BarcodeWake 不是医疗器械、紧急警报服务或睡眠阶段追踪器。任何闹钟应用都无法保证唤醒或补偿设备不可用的情况。[事实与限制页面](../facts.md) 列出了这些界限，而[可用性](../availability.md) 则将公共商店的证据与更新的源代码功能区分开来。
