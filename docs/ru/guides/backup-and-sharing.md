# Безопасное резервное копирование и обмен сигналами тревоги BarcodeWake

Используйте экспорт в формате JSON для сохранения или перемещения данных вашего приложения, штрих-код резервной копии в формате PDF для распечатки при восстановлении, а также общий QR-код настроек, когда другому человеку нужна только структура сигнала тревоги. При обмене намеренно опускаются зарегистрированные секреты и история.

## Выберите формат для задачи

Текущий источник предоставляет различные пути обмена, поскольку резервное копирование и обмен — это не одна и та же операция. Резервная копия JSON предназначена для структурированной передачи данных и восстановления. Резервная копия PDF превращает материал для восстановления в документ со штрих-кодом для печати. QR-код настроек намеренно более узкий: он может передать ограниченную конфигурацию сигнала тревоги без переноса зарегистрированных значений штрих-кодов, идентификаторов NFC, PIN-кодов или истории.

Не рассматривайте QR-код настроек как полную резервную копию устройства. Получатель должен зарегистрировать свои собственные физические коды и локально проверить разрешения. Текущий обмен настройками также ограничивает количество сигналов тревоги, которые он переносит, поэтому проверьте импортированный результат, а не предполагайте, что все расписание переместилось. В [фактах о продукте](../facts.md) записаны эти границы.

## Создайте и защитите личную резервную копию

Используйте действие экспорта, доступное в установленной сборке, выберите JSON или резервную копию для печати в соответствии с планом восстановления и сохраните результат в месте, которое вы контролируете. Резервная копия может раскрыть имена сигналов тревоги, расписания и другие данные конфигурации даже когда зарегистрированные значения исходного кода защищены или опущены. Обращайтесь с ней как с личными рутинными данными: избегайте публичных ссылок, общих принтеров и недоверенных каналов обмена сообщениями.

После экспорта подтвердите, что файл можно найти и что его временная метка соответствует предполагаемой резервной копии. Не удаляйте исходные данные приложения только потому, что команда экспорта сообщила об успехе. Тестирование восстановления — единственный надежный способ проверки, но выполняйте его на безопасном устройстве или после создания второй копии, чтобы само тестирование не стало событием потери.

## Обменивайтесь настройками без раскрытия секретов

Создавайте QR-код настроек только для тех сигналов тревоги, которые должен получить получатель. Получатель сканирует его, просматривает импортированное расписание и предоставляет свои собственные коды, NFC-метку или данные для восстановления. Эта конструкция предотвращает передачу общей конфигурации, которая молчаливо передает физический ключ, отключающий чужой сигнал тревоги другого человека.

После импорта каждый человек должен выполнить полное [тестирование настройки сигнала тревоги](set-up-an-alarm.md). Разрешения, датчики и ограничения операционной системы не передаются в QR-коде. Если импортированный сигнал тревоги не появляется при блокировке, следуйте [устранению неполадок доставки сигнала тревоги](../help/alarm-delivery.md).

Исходная версия и версия хранилища отличались во время этой проверки, поэтому установленная публичная сборка может не предоставлять все описанные здесь варианты обмена. В [доступности](../availability.md) объясняется, как интерпретировать возможности только из исходного кода.
