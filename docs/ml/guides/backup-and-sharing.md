# BarcodeWake അലാറമുകൾ സുരക്ഷിതമായി ബാക്കപ്പ് ചെയ്യുകയും പങ്കിടുകയും ചെയ്യുക

നിങ്ങളുടെ സ്വന്തം ആപ്പ് ഡാറ്റ സംരക്ഷിക്കുന്നതിനോ മാറ്റുന്നതിനോ JSON export ഉപയോഗിക്കുക, വീണ്ടെടുക്കലിനായി അച്ചടിക്കാവുന്ന PDF ബാക്കപ്പ് barcode ഉപയോഗിക്കുക, മറ്റൊരാൾക്ക് അലാറം ഘടന മാത്രം ആവശ്യമുള്ളപ്പോൾ setup QR പങ്കിടൽ ഉപയോഗിക്കുക. പങ്കിടൽ ഉദ്ദേശിച്ചുള്ളതായി രജിസ്റ്റർ ചെയ്ത രഹസ്യങ്ങളെയും ചരിത്രത്തെയും ഒഴിവാക്കുന്നു.

## ജോലിക്കായി ഫോർമാറ്റ് തിരഞ്ഞെടുക്കുക

നിലവിലെ ഉറവിടം വ്യത്യസ്ത എക്സ്ചേഞ്ച് പാതകൾ നൽകുന്നു, കാരണം ബാക്കപ്പും പങ്കിടൽ ഒരേ പ്രവർത്തനമല്ല. JSON ബാക്കപ്പ് ഘടനാപരമായ ഡാറ്റ കൈമാറ്റത്തിനും പുനസ്ഥാപനത്തിനും ഉദ്ദേശിച്ചതാണ്. PDF ബാക്കപ്പ് വീണ്ടെടുക്കൽ മെറ്റീരിയലിനെ അച്ചടിക്കാവുന്ന barcode ഡോക്യുമെന്റാക്കി മാറ്റുന്നു. Setup QR ഉദ്ദേശപ്രകാരം കൂടുതൽ സംകുചിതമാണ്: ഇത് രജിസ്റ്റർ ചെയ്ത barcode മൂല്യങ്ങൾ, NFC ഐഡന്റിഫയറുകൾ, PIN-കൾ അല്ലെങ്കിൽ ചരിത്രം വഹിക്കാതെ പരിധിയിത അലാറം കോൺഫിഗറേഷൻ കൈമാറാൻ കഴിയും.

Setup QR-യെ പൂർണ്ണ ഉപകരണ ബാക്കപ്പായി കണക്കാക്കരുത്. സ്വീകർത്താവ് സ്വന്തം ഫിസിക്കൽ കോഡുകൾ രജിസ്റ്റർ ചെയ്യുകയും ലോക്കലായി അനുമതികൾ അവലോകനം ചെയ്യുകയും വേണം. നിലവിലെ setup പങ്കിടൽ എത്ര അലാറമുകൾ വഹിക്കുന്നു എന്നതിൽ പരിമിതികളുണ്ട്, അതിനാൽ ഓരോ ഷെഡ്യൂൾ നീങ്ങിയതായി കണക്കാക്കാതെ ഇറക്കുമതി ചെയ്ത ഫലം പരിശോധിക്കുക. [ഉൽപ്പന്ന വസ്തുതകൾ](../facts.md) ഈ അതിർവരമ്പുകൾ രേഖപ്പെടുത്തുന്നു.

## ഒരു സ്വകാര്യ ബാക്കപ്പ് സൃഷ്ടിക്കുകയും സംരക്ഷിക്കുകയും ചെയ്യുക

ഇൻസ്റ്റാൾ ചെയ്ത ബിൽഡിൽ ലഭ്യമായ എക്സ്പോർട്ട് ആക്ഷൻ ഉപയോഗിക്കുക, JSON അല്ലെങ്കിൽ വീണ്ടെടുക്കൽ പദ്ധതിപ്രകാരം അച്ചടിക്കാവുന്ന ബാക്കപ്പ് തിരഞ്ഞെടുക്കുക, ഫലം നിങ്ങൾ നിയന്ത്രിക്കുന്ന എവിടെയെങ്കിലും സംരക്ഷിക്കുക. രജിസ്റ്റർ ചെയ്ത റോ കോഡ് മൂല്യങ്ങൾ സംരക്ഷിക്കപ്പെട്ടതോ ഒഴിവാക്കിയതോ ആണെങ്കിലും ഒരു ബാക്കപ്പ് അലാറം പേരുകൾ, ഷെഡ്യൂളുകൾ, മറ്റ് കോൺഫിഗറേഷനുകൾ വെളിപ്പെടുത്താൻ കഴിയും. ഇതിനെ  شخصي റൂട്ടിൻ ഡാറ്റയായി കൈകാര്യം ചെയ്യുക: പബ്ലിക് ലിങ്കുകൾ, പങ്കിട്ട പ്രിന്ററുകൾ, വിശ്വസനീയരല്ലാത്ത മെസേജിംഗ് ചാനലുകൾ ഒഴിവാക്കുക.

എക്സ്പോർട്ട് ചെയ്ത ശേഷം, ഫയൽ കണ്ടെത്താനാകുമെന്നും അതിന്റെ ടൈംസ്റ്റാമ്പ് ഉദ്ദേശിച്ച ബാക്കപ്പുമായി പൊരുത്തപ്പെടുമെന്നും സ്ഥിരീകരിക്കുക. ഒരു എക്സ്പോർട്ട് കമാൻഡ് വിജയിച്ചതായി റിപ്പോർട്ട് ചെയ്തതിനാൽ മാത്രം യഥാർത്ഥ ആപ്പ് ഡാറ്റ ഇല്ലാതാക്കരുത്. പുനസ്ഥാപന ടെസ്റ്റിംഗാണ്  единственный വിശ്വസനീയമായ പരിശോധന, എന്നാൽ ഇത് സുരക്ഷിത ഉപകരണത്തിലോ രണ്ടാമത്തെ പകർപ്പ് ഉണ്ടാക്കിയ ശേഷമോ നടത്തുക, അതുവഴി ടെസ്റ്റ് തന്നെ ഒരു നഷ്ടസംഭവമാകാതിരിക്കുക.

## രഹസ്യങ്ങൾ പങ്കിടാതെ setup പങ്കിടുക

സ്വീകർത്താവിന് ലഭിക്കേണ്ട അലാറമുകൾക്കായി മാത്രം ഒരു setup QR സൃഷ്ടിക്കുക. സ്വീകർത്താവ് അത് scan ചെയ്യുക, ഇറക്കുമതി ചെയ്ത ഷെഡ്യൂൾ അവലോകനം ചെയ്യുക, സ്വന്തം കോഡ്, NFC ടാഗ് അല്ലെങ്കിൽ വീണ്ടെടുക്കൽ വിശദാംശങ്ങൾ നൽകുക. ഈ രൂപകൽപ്പന ആരെങ്കിലും മറ്റൊരാളുടെ അലാറം റദ്ദാക്കുന്ന ഫിസിക്കൽ കീ നിശ്ശബ്ദമായി കൈമാറുന്നതിൽ നിന്ന് തടയുന്നു.

ഇറക്കുമതിക്ക് ശേഷം, ഓരോരുത്തരും പൂർണ്ണ [alarm setup test](set-up-an-alarm.md) പ്രവർത്തിപ്പിക്കണം. അനുമതികൾ, സെൻസറുകൾ, ഓപ്പറേറ്റിംഗ്-സിസ്റ്റം നിയന്ത്രണങ്ങൾ എന്നിവ QR-ൽ കൈമാറ്റം ചെയ്യപ്പെടുന്നില്ല. ലോക്കായിരിക്കെ ഇറക്കുമതി ചെയ്ത അലാറം പ്രത്യക്ഷപ്പെടാതിരിക്കുകയാണെങ്കിൽ, [alarm delivery troubleshooting](../help/alarm-delivery.md) പിന്തുടരുക.

ഈ  аудит സമയത്ത് ഉറവിടവും സംഭരണവും പതിപ്പുകളിൽ വ്യത്യാസമുണ്ടായിരുന്നു, അതിനാൽ ഇൻസ്റ്റാൾ ചെയ്ത പബ്ലിക് ബിൽഡ് ഇവിടെ വിവരിച്ച എല്ലാ എക്സ്ചേഞ്ച് ഓപ്ഷനുകളും വെളിപ്പെടുത്തിയേക്കില്ല. [Availability](../availability.md) ഉറവിട-മാത്രമായ കഴിവുകൾ എങ്ങനെ വ്യാഖ്യാനിക്കണം എന്നത് വിശദീകരിക്കുന്നു.
