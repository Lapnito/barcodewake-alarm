# Резервне копіювання та безпечне спільне використання сповіщень BarcodeWake

Використовуйте експорт JSON для збереження або переміщення власних даних програми, відсканований PDF-код для відновлення та QR-код налаштування, коли іншій особі потрібна лише структура сповіщення. Спільний доступ навмисно не включає зареєстровані секрети та історію.

## Виберіть формат для завдання

Поточне джерело надає різні шляхи обміну, оскільки резервне копіювання та спільний доступ — це не одна й та сама операція. Резервна копія JSON призначена для структурованого передавання даних та відновлення. PDF-резервна копія перетворює матеріали для відновлення на друкований документ із штрих-кодом. QR-код налаштування навмисно вужчий: він може передати обмежену конфігурацію сповіщення без перенесення зареєстрованих значень штрих-кодів, ідентифікаторів NFC, PIN-кодів чи історії.

Не розглядайте QR-код налаштування як повну резервну копію пристрою. Отримувач має зареєструвати власні фізичні коди та переглянути дозволи локально. Поточне спільне використання налаштувань також обмежує кількість сповіщень, які він містить, тому перевірте результат імпорту, а не припускайте, що кожне розкладання перемістилося. [Факти про продукт](../facts.md) фіксують ці межі.

## Створіть і захистіть особисту резервну копію

Використовуйте дію експорту, доступну в встановленій збірці, виберіть JSON або відскановану резервну копію згідно з планом відновлення та збережіть результат там, де ви маєте контроль. Резервна копія може розкрити назви сповіщень, розклади та інші налаштування, навіть якщо зареєстровані сирі значення кодів захищені або опущені. Поводьтеся з нею як з особистими рутинними даними: уникайте публічних посилань, спільних принтерів та ненадійних каналів обміну повідомленнями.

Після експорту підтвердьте, що файл можна знайти і що його мітка часу відповідає запланованому резервному копіюванню. Не видаляйте оригінальні дані програми лише тому, що команда експорту повідомила про успіх. Тестування відновлення — єдиний надійний спосіб перевірки, але виконуйте його на безпечному пристрої або після створення другої копії, щоб сам тест не став подією втрати.

## Діліться налаштуваннями, не ділячись секретами

Створюйте QR-код налаштування лише для сповіщень, які отримувач має отримати. Отримувач сканує його, переглядає імпортований розклад і надає власний код, NFC-тег або відомості для відновлення. Ця конструкція запобігає тому, щоб спільна конфігурація непомітно передавала фізичний ключ, який відхиляє чиєсь інше сповіщення.

Після імпорту кожна особа має виконати повне [тестування налаштування сповіщення](set-up-an-alarm.md). Дозволи, датчики та обмеження операційної системи не передаються в QR. Якщо імпортоване сповіщення не з'являється під час блокування, дотримуйтесь [усунення несправностей доставки сповіщень](../help/alarm-delivery.md).

Версії вихідного коду та магазину відрізнялися під час цієї перевірки, тому встановлена публічна збірка може не відображати кожну опцію обміну, описану тут. [Доступність](../availability.md) пояснює, як інтерпретувати можливості, доступні лише у вихідному коді.
