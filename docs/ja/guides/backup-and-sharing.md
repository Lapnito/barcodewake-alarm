# BarcodeWakeアラームを安全にバックアップおよび共有する

独自のアプリデータを保存または移動する場合はJSONエクスポートを、復元用の印刷可能なPDFバックアップバーコードが必要な場合はPDFバックアップを、他の人にアラーム構造のみを渡す場合はセットアップQR共有を使用します。共有では登録済みのシークレットと履歴が意図的に省略されます。

## 用途に応じたフォーマットの選択

現在のソースでは、バックアップと共有が異なる操作であるため、いくつかのエクスポートパスが提供されています。JSONバックアップは構造化データの転送と復元を目的としています。PDFバックアップは復元素材を印刷可能なバーコードドキュメントに変換します。セットアップQRは意図的に限定的で、登録済みバーコード値、NFC識別子、PINや履歴を含まずにアラーム設定を渡すことができます。

セットアップQRを完全なデバイスバックアップと見なさないでください。受信者は自分の物理コードを登録し、ローカルで権限を確認する必要があります。現在のセットアップ共有は運ぶことができるアラームの数に制限があるため、すべてのスケジュールが移動したと想定せず、インポート結果を検証してください。[製品情報](../facts.md)にこれらの境界が記録されています。

## 個人用バックアップの作成と保護

インストール済みビルドで提供されるエクスポート機能を使用し、復元計画に応じてJSONまたは印刷可能なバックアップを選択し、結果を自分が管理する場所に保存してください。バックアップは、登録済み生コード値が保護または省略されている場合でも、アラーム名、スケジュール、その他の設定情報を開示する可能性があります。個人のルーティンデータと同じように扱い、パブリックリンク、共用プリンター、信頼できないメッセージングチャネルを避けてください。

エクスポート後、ファイルが見つかることとそのタイムスタンプが意図したバックアップと一致することを確認してください。エクスポートコマンドが成功報告をしたからというだけで、元のアプリデータを削除しないでください。リストアテストだけが信頼できる確認方法ですが、テスト自体が損失イベントにならないように、安全なデバイスで、またはコピーを作成した後で行ってください。

## シークレットを共有せずにセットアップを共有する

受信者が受け取るべきアラームに対してのみ、セットアップQRを生成してください。受信者はそれをスキャンし、インポートされたスケジュールを確認し、自分のコード、NFCタグまたは復元詳細を提供します。この設計により、共有された設定が他の人のアラームを解除する物理キーを黙って転送することを防ぎます。

インポート後、各人は完全な[アラーム設定テスト](set-up-an-alarm.md)を実行してください。権限、センサー、OSの制限はQRでは転送されません。インポートされたアラームがロック中に表示されない場合は、[アラーム配信のトラブルシューティング](../help/alarm-delivery.md)を参照してください。

この監査ではソースとストアのバージョンが異なっていたため、インストールされているパブリックビルドはここで説明されているすべてのエクスポートオプションを表示しない場合があります。[可用性](../availability.md)には、ソース限定機能の解釈方法が記載されています。
