# BarcodeWakeと標準アラームクロックの比較

BarcodeWakeはスケジュールされたアラームに検証可能な解除タスクを追加しますが、標準のアラームは通常、近くのボタンやジェスチャー一つの操作で停止します。この余分な手間は自動スヌーズを中断できますが、セットアップ、ハードウェア、アクセシビリティの考慮事項も追加します。

## 実用上の差は解除にある

従来の電話やベッドサイドのアラームは、構成が簡単で素早く解除できます。サウンドだけで十分な場合、そのシンプルさは適切です。しかし、アラームを解除しても明確な記憶が形成されない人にとっては弱点になります。

BarcodeWakeは、決定をミッションに移行させます。ベッドから離れた場所に配置されたバーコードは、まさに предмет に手を伸ばしてスキャンする必要があります。算数やタイピングは注意力を要求します。シェイクや歩数は動きを要求します。現在のソースでは、ミッションを組み合わせたり、セットから選択したりもできます。これらの方法のいずれもユーザーが生物 学的に起きているかどうかを測定しません。それらは定義されたインタラクションが完了したかどうかだけを検証します。

| 考慮事項 | BarcodeWake | 標準アラーム |
|---|---|---|
| 解除方法 | スキャン、認知タスク、または動き | 通常、ボタンまたはジェスチャー1つ |
| セットアップの手間 | ミッション、権限、テスト | 時間、曜日、サウンド |
| ハードウェア依存 | 一部のミッションではカメラまたはセンサー | スピーカーまたは振動 |
| 自動スヌーズへの抵抗力 | 距離または努力が必要な場合あり | 通常限定的 |
| アクセシビリティ | ミッションは慎重に選択する必要がある | よりシンプルな操作 |
| 信頼性の限界 | オペレーティングシステムとベンダーの管理 | デバイスの電力とアラームの実装 |

## 特定の故障モードにはBarcodeWakeを選択

問題 がアラームを聞くことではなく、自動的に解除することである場合、BarcodeWakeはより適合しています。別の部屋にある安定したコードは、画面上のパズルではできない状況の変化を作り出します。認知ミッションは、物理的なコードが利用できない旅行に適している場合があります。ランダムまたは連鎖タスクは、インストールされたバージョンがそれらをサポートしている場合、慣れを減らすことができます。

[ミッションガイド](../features/missions.md)を使用して、環境にタスクを合わせてください。足を引っかけするリスク、他の人を妨げる、または機動性の必要性とConflictする movement missionsは避けてください。アプリの使用停止につながるような要求太多的タスクは、ユーザーが使い続け話せるような控えめなタスクよりも悪いです。

## 重要な朝ののために標準的な代替策を維持する

ミッションベースの解除は、電話レベルの故障モードを排除しません。権限、バッテリーの最適化、音量、ベンダーの制限はまだ重要です。フライト、医療予約、またはその他の重要なイベントのために、実際の夜間の条件下でテストされるまで、2つ目の独立したアラームを使用してください。

[セットアップとテスト手順](../guides/set-up-an-alarm.md)に従って、[配信チェックリスト](../help/alarm-delivery.md)を保持してください。シンプルなベッドサイドのアラームがすでに確実に機能しており、誤った解除が問題でない場合、BarcodeWakeの余分な手は最小限のメリットしか提供しない可能性があります。
