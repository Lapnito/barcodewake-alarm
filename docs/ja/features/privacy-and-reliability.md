# BarcodeWakeのプライバシーとアラームの信頼性

BarcodeWakeは、ドキュメント化されたアラーム設定とミッションデータをデバイスに保持し、アプリアカウントを必要としません。現在のコードパスは、登録されたコード値をハッシュ化します。オプションのテレメトリはデフォルトで無効と記載されていますが、アラームの配信はシステム権限とベンダーの制御に依存します。

## ローカルデータはシステム依存性をなくさない

ローカルストレージは、通常の目覚まし設定にBarcodeWakeクラウドアカウントを必要としないことを意味します。アラーム記録、履歴、設定は、アプリのローカルデータレイヤーを通じて処理されます。登録されたバーコード、QR、NFCの値は、現在のストレージとインポートパスでSHA-256ハッシュとして表されるため、マッチングのために生の元の値を保持することを避けます。

ハッシュ化はすべてのアプリ記録の暗号化と同じではなく、ローカルストレージはバックアップではありません。ロック解除されたデバイスにアクセスできる人は、アプリを介してアラーム名、スケジュール、履歴を見る可能性があります。電話を紛失したりリセットしたりすると、ユーザーがエクスポートを作成していない限り、ローカルデータが失われる可能性があります。形式とその異なる目的については、[バックアップと共有](../guides/backup-and-sharing.md)を参照してください。

プライバシーポリシーでは、オプションのテレメトリはデフォルトでオフであり、有効になった場合は集計処理について説明しています。そのため、このドキュメントでは、アプリがネットワーク経由で通信できないという広範な主張は行っていません。確認された事実として、より狭い範囲を述べていません：コア操作とデータはローカルであり、製品アカウントは不要であり、チェックされたプロジェクトに広告SDKの依存関係が表示されていません。

## 信頼性は共有の責任です

BarcodeWakeはアラームをスケジュールして表示できますが、バックグラウンド処理がいつ実行されるか、および哪些の中断が許可されるかは、オペレーティングシステムが決定します。通知権限、正確なアラームへのアクセス、サイレントモードまたは集中モード、バッテリー最適化、アプリの自動一時停止、メーカーのタスクキラーはすべて関係する可能性があります。アプリ内の信頼性ツールは設定リスクを特定し、ユーザーに設定を指示すことができますが、システムポリシーを上書きすることはできません。

インストール後、画面をロックし、夜間の使用と同じ電力モードで電話を置いてテストしてください。システムアップデート、バッテリーセーバーの変更、アプリの再インストール後にそのテストを繰り返してください。デバイスを充電し、音量を適切に設定し、選択したミッションを物理的に利用可能な状態に保ってください。テストが失敗した場合は、[アラーム配信のトラブルシューティング](../help/alarm-delivery.md)に従ってください。

## プライバシーと信頼性が約束しないこと

BarcodeWakeは医療機器、緊急アラートサービス、睡眠段階トラッカーではありません。アラームアプリが目覚めを保証したり、利用できないデバイスの補償したりすることはできません。[事実と限界のページ](../facts.md)にはこれらの境界が記載されており、[可用性](../availability.md)では、パブリックストアの証拠と新しいソース能力を区別しています。
